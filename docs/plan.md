## Depends on

`pathattr`, for the BGP PDUs that BMP encapsulates. Route Monitoring and Route Mirroring messages carry
a whole BGP UPDATE and Peer Up carries the OPEN messages of the session; decoding those is pathattr's
job (`D:\code\pathattr`). Everything else in [../ROADMAP.md](../ROADMAP.md) is this repository's own:
the BMP framing, the per-peer header, Initiation, Termination, Peer Up framing and the collector
server decode and run without it, with PDU bodies kept as bytes. Only the row `messages.decode-bgp-pdus`
and the rows that read UPDATE contents wait for pathattr.

## Sequencing rules

- At most two projects in the portfolio carry real effort at once. A third is not started, and
  no obligation is taken here, while those two are open.
- No new shell is created while any Tier 1 project still has an unimplemented obligation. The
  READMEs of the 27 generated shells are already the maintenance liability, and the failure mode
  of this portfolio is prose outrunning code rather than under-building.
- A project freezes to Tier 4 when its first release finds no external user, and a shell is
  retired publicly when a competitor ships what it promised rather than left to rot - the
  retirement is announced, not a README quietly left to go stale.
